# Каталог `.agents`

Этот каталог предназначен для единой, независимой от конкретного агента конфигурации проекта согласно [AGENTS-1](https://github.com/agentsfolder/spec).

## Обязательная структура

```text
.agents/
├── manifest.yaml          # Реестр конфигурации и значения по умолчанию.
├── prompts/               # Текстовые инструкции для агента.
│   ├── base.md            # Общие инструкции.
│   ├── project.md         # Инструкции, специфичные для проекта.
│   └── snippets/          # Переиспользуемые фрагменты инструкций.
├── modes/                 # Режимы работы агента в Markdown с YAML front matter.
│   ├── plan.md            # Планирование.
│   ├── code.md            # Разработка.
│   └── review.md          # Ревью.
├── policies/              # YAML-политики прав, ограничений и подтверждений.
├── skills/                # Навыки: каждый в <name>/SKILL.yaml.
├── scopes/                # YAML-переопределения для путей, в том числе монорепозитория.
├── profiles/              # Именованные наложения конфигурации: dev, ci и т. п.
├── schemas/               # JSON Schema для проверки конфигурации.
└── state/                 # Локальное состояние, не добавляемое в Git.
    ├── .gitignore         # Исключает state.yaml из контроля версий.
    └── state.yaml         # Выбранные mode, profile и backend.
```

Все перечисленные каталоги и `manifest.yaml` обязательны для соответствия AGENTS-1, хотя `skills/`, `scopes/`, `profiles/` и `schemas/` могут быть пустыми.

## Основные правила

- `manifest.yaml` объявляет `specVersion`, конфигурацию по умолчанию и разрешённые modes, policies и skills.
- Файлы в `prompts/` и `modes/` пишутся в Markdown; файлы политик, профилей и scopes -- в YAML UTF-8.
- Каждая policy определяет доступ к файловой системе, выполнению команд, сети и MCP. Запрет всегда имеет приоритет над разрешением.
- Каждый skill должен находиться в `skills/<name>/SKILL.yaml` и содержать стабильный идентификатор, версию, способ активации, интерфейс и требования к возможностям.
- Scope сопоставляется с путями по glob-шаблонам `**`; при нескольких совпадениях применяется самый специфичный.
- `state/state.yaml` носит рекомендательный характер: он выбирает уже объявленные mode или profile, но не переопределяет каноническую конфигурацию.
- `schemas/` может генерироваться инструментами. Инструменты не должны менять канонические исходные файлы без явного запроса пользователя.

## Текущее состояние

Сейчас используются существующие навыки в `skills/` и общие проектные инструкции в `prompts/project.md`. Остальные элементы структуры следует добавить при миграции проекта на полную конфигурацию AGENTS-1.
