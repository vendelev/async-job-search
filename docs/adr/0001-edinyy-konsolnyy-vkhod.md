# Единый консольный вход

Приложение запускается через единый `backend/bin/app.php` и `AppModule`.
Команды остаются существующими invokable-классами `Presentation\Console`, помеченными `#[AsCommand]`;
`AppModule` собирает их по `Core\Presentation\Config\ConsoleCommandTag` и передаёт в Symfony Console.

Конфигурации `PostgresEnv`, `HttpServerEnv` и `HabrCareerEnv` передаются в контекстные `*Di` как
`Closure(): *Env`. Замыкание вызывается только при запуске команды, которая использует соответствующую конфигурацию.
Поэтому `bin/app.php list` не требует переменных окружения, а `migrate` не требует HTTP-параметров и cookie Habr Career.
Так также сохраняется тестовый шов: тесты передают готовое окружение через замыкание, не изменяя окружение процесса.

`MigrationProviderTag` и `ConsoleCommandTag` находятся в `Core\Presentation\Config`, потому что это технические
контракты композиции нескольких модулей. `Core` не зависит от прикладных модулей; теги не используются в Domain,
Application или Infrastructure.

## Рассмотренные варианты

**Отдельные bin-скрипты.** Отклонено: они дублируют композиционные корни и не дают общего интерфейса Symfony Console.

**Читать окружение на верхнем уровне bin-скрипта.** Отклонено: команды требуют несвязанные с ними переменные окружения.

**Читать окружение внутри модулей.** Отклонено: это убирает возможность передать в модуль готовую конфигурацию из теста.

**Явный список команд и провайдеров миграций в `AppModule`.** Отклонено: новый контекст должен добавлять их без
изменения корневого модуля.
