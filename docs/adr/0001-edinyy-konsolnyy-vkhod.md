# Единый консольный вход

Приложение запускается через единый `backend/bin/app.php` и `AppModule`.
Команды остаются существующими invokable-классами `Presentation\Console`, помеченными `#[AsCommand]`;
`AppModule` собирает их по `Core\Presentation\Config\ConsoleCommandTag` и передаёт в Symfony Console.

`Application::addCommands()` создаёт все команды сразу, поэтому без дополнительных мер `migrate` собирал бы
HTTP-сервер, а `list` требовал бы cookie Habr Career. Команды регистрируются как ленивые сервисы
(`ObjectConfig::lazy()`, PHP-прокси `ReflectionClass::newLazyProxy()`): Symfony Console получает прокси,
а реальный объект и весь его граф зависимостей строятся при первом обращении, то есть при запуске команды.
Имя и описание берутся из `#[AsCommand]` рефлексией, поэтому `list` прокси не инициализирует.
Сами команды принимают обычные типизированные зависимости.

Конфигурации `PostgresEnv`, `HttpServerEnv` и `HabrCareerEnv` передаются в контекстные `*Di` как
`Closure(): *Env`. Замыкание вызывается только при построении конфигурации, то есть при запуске команды,
которая её использует. Так сохраняется тестовый шов: тесты передают готовое окружение через замыкание,
не изменяя окружение процесса. Дальше конфигурация остаётся обычным сервисом: `HabrCareerVacancySource`
получает cookie строкой через `HabrCareerVacancySourceFactory`, а не замыканием.

`MigrationProviderTag` и `ConsoleCommandTag` находятся в `Core\Presentation\Config`, потому что это технические
контракты композиции нескольких модулей. `Core` не зависит от прикладных модулей; теги не используются в Domain,
Application или Infrastructure.

## Рассмотренные варианты

**Отдельные bin-скрипты.** Отклонено: они дублируют композиционные корни и не дают общего интерфейса Symfony Console.

**Читать окружение на верхнем уровне bin-скрипта.** Отклонено: команды требуют несвязанные с ними переменные окружения.

**Читать окружение внутри модулей.** Отклонено: это убирает возможность передать в модуль готовую конфигурацию из теста.

**Явный список команд и провайдеров миграций в `AppModule`.** Отклонено: новый контекст должен добавлять их без
изменения корневого модуля.

**`Closure(): T` для всех зависимостей команд.** Отклонено: откладывает создание графа, но протекает в сами классы —
`MigrateCommand`, `ServerHttp`, `DiscoverVacanciesDaemon` и даже `HabrCareerVacancySource` из Infrastructure
принимали бы замыкания вместо зависимостей. `lazy()` даёт тот же эффект, не меняя их сигнатуры.

**`Application::setCommandLoader()` с `LazyCommand`.** Отклонено: решает ту же задачу, но требует отдельного
дескриптора команды и загрузчика, потому что `Dic::taggedList()` резолвит сами сервисы, а `Application::all()`
запрашивает у загрузчика каждую команду. `lazy()` обходится без этой инфраструктуры.
